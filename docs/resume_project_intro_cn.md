## 项目一：TicketFlow｜面向客服与 IT 服务台场景的工单协同 Agent
技术栈：`Python`、`LangGraph`、`RAG`、`Chroma`、`MCP`、`Streamlit`、`SQLite`

- 基于 `LangGraph` 设计状态化工单处理 workflow，完成 `分诊 -> 检索 -> 动作建议 -> 审批 -> 执行 -> 回复 -> 审计` 闭环，并将退款、升级等高风险动作纳入人工审批与审计追踪链路。  
- 以 `360` 条公开映射工单构建 canonical 结构化评测集，并固定为 `240/40/80` 的 `train/dev/eval` 划分；在 `80` 条 held-out 样本上，实现 **工单类别判断准确率** `96.3%`、**类别宏平均 F1** `0.962`、**动作类型判断准确率** `88.7%`、**审批需求 F1** `89.7%`、**目标状态预测准确率** `88.7%`。  
- 构建面向知识库、策略规则与历史工单的混合 `RAG` 检索层，采用关键词检索与向量检索联合召回证据；主链评测中 **策略命中率** 与 **历史案例命中率** 均从 `0%` 提升到 `100%`，用于增强动作建议与客户回复的证据支撑。  
- 将升级通知与知识候选沉淀抽象为独立 `MCP` 邮件工具层，支持真实 SMTP 协议链路与外部失败非阻塞回退；结合节点级主链评测，完成外部协同闭环验证。  

## 项目二：MiniMind-Ticket｜面向工单场景的本地小模型领域化与双 LoRA 接入
技术栈：`Python`、`MiniMind`、`LoRA`、`PEFT`、`OpenAI-compatible API`

- 针对“单 LoRA 混训结构化决策与真实客服回复相互干扰”的问题，将本地模型拆分为 **Structured LoRA** 与 **Reply LoRA** 两个独立适配器：前者负责 `triage / propose_action`，后者负责 `draft_reply`。  
- 基于 `360` 条 canonical 结构化工单 gold 数据构建独立训练与评测集；在 `80` 条 held-out 结构化样本上，**Structured LoRA** 达到 **工单类别判断准确率** `96.3%`、**动作类型判断准确率** `88.7%`、**目标状态预测准确率** `88.7%`、**严格 JSON 有效率** `100%`。  
- 基于 `JDDC` 真实中文客服对话构建回复训练集与 `100` 条 held-out 回复评测集；新的 **Reply LoRA** 将 **真实回复得分** 提升到 `0.223`，显著优于 `base model` 的 `0.071` 和旧 `single-LoRA mixed` 的 `0.050`，同时将 **重复回复率** 从 `0.93 / 0.40` 降到 `0.18`。  
- 将双 LoRA 以两个独立本地 OpenAI-compatible 端口接入 `TicketFlow`（`9011` 结构化、`9012` 回复）；在 `24` 条 held-out 工单上，**本地结构化节点覆盖率**、**本地回复节点覆盖率**、**回复可用率** 均达到 `100%`，并将 **后端错误率** 从旧 mixed 版本的 `50%` 降到 `0%`。
